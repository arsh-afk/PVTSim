Core Modules

PVT (Photovoltaic‑Thermal) Solver

The src/aquasolar/pvt package implements a coupled electro‑thermal model. Key equations (EQ‑PVT‑01 …‑04) relate electrical output, useful heat, cell‑to‑fluid resistance and fluid energy balance. Main entry points are collector.pvt_solve() and collector.pvt_series_solve(), which orchestrate the solver defined in coupled.py. Supporting files provide temperature‑dependent electrical efficiency (electrical.py), thermal extraction (thermal.py), and a PV‑only reference model (pv_only.py).

Weather & Irradiance

src/aquasolar/weather supplies solar position (solar_geometry.py), angle‑of‑incidence modifiers (IAM models in iam.py), soiling degradation (soiling.py) and POA irradiance transposition (transposition.py). The module relies on pvlib for astronomical calculations and implements custom IAM curves (Klucher, Preiss).

Electrical Balance

The src/aquasolar/electrical/balance.py file computes system‑wide power balance, handling grid import/export limits, battery state‑of‑charge, and optional curtailment. It provides electrical_balance() for a single timestep and electrical_balance_series() for time‑series simulation.

Solar Loop & Pump

Control logic (controller.py) decides pump operation based on temperature differentials, over‑heat and freeze protection. Pipe thermal/hydraulic calculations (pipes.py) use NTU heat‑loss and Darcy‑Weisbach pressure‑drop formulas. Pump performance (pump.py) models flow and power curves.

Stratified Tank Storage

The src/aquasolar/tank suite models a vertically stratified hot‑water tank. grid.py defines the TankGrid nodal representation. step.py advances the state each timestep, applying advection, heat loss and mixing. Mixing models (mixing.py) include ideal and stratified options. Auxiliary heating (auxiliary_heating.py) and draw logic (draw.py) simulate domestic hot‑water usage.

Water Treatment

Stages (stages.py) encode individual treatment units (sediment filter, carbon filter, UV, ultrafiltration, nanofiltration, remineralisation). train.py builds treatment pathways (A/B/C) by chaining stages and applying log‑reduction formulas.

Economics

Levelised cost of energy and related financial metrics are calculated in src/aquasolar/economics/lcoe.py. Functions compute LCOE, pay‑back periods, NPV and bottled‑water cost avoidance.

Uncertainty Quantification

Monte‑Carlo sampling (monte_carlo.py) and Sobol sensitivity analysis (sobol.py) propagate parameter uncertainty through the simulation.

IO Helpers

Utilities for reading CSV/YAML tables (tables.py), time‑series data (timeseries.py) and generating quality reports (quality_report.py).

Registry & Validation

Parameter schema definitions (registry/schema.py) and loading/validation logic (registry/load.py) ensure all user inputs conform to expected types and ranges.

Integration & CLI

The entry points src/aquasolar/__main__.py, cli.py and integrator.py wire together configuration, the weather model, PVT solver, tank, electrical balance and reporting.

Test Coverage

There are 82 unit tests across 7 domains. All tests pass, providing confidence in electrical balance, PVT physics, water‑treatment pathways, economics, uncertainty methods and tank dynamics.

System Architecture

Data flow follows a clear pipeline:

  1. Parameter & timeseries ingestion (registry → io)
  2. Weather model (solar position → IAM → irradiance)
  3. PVT solver (electrical + thermal coupling)
  4. Electrical balance (grid + battery management)
  5. Tank storage (stratified thermal storage, mixing, draws)
  6. Water‑treatment pathways (stage chaining)
  7. Reporting (metrics → dashboard)

The project is fully parameterised – every literal constant appears in the inputs/parameters YAML files – enabling easy scenario analysis.
